# APIs, coleções e valores

Versões e status na [matriz](java-version-matrix.md). Exceto Sequenced Collections (21) e Gatherers (24), todos os exemplos abaixo são compatíveis com 17/21/25. Trechos supõem imports java.util, java.util.stream, java.time ou java.math apropriados e variáveis de domínio declaradas. Veja [programa 17](../examples/Java17Examples.java).

| Recurso; origem/finalização | O que faz e quando usar | EVITAR → PREFERIR | Justificativa, impacto e exceções |
|---|---|---|---|
| Optional; 8/8 | Retorno que modela ausência individual | `if (found.isPresent()) return found.get(); throw missing;` → `return found.orElseThrow(() -> new NotFound(id));` | Contrato explícito; não retorne null no lugar de Optional. Evite campos de entidades, parâmetros obrigatórios e Optional de coleção quando vazio basta; siga contrato existente. `orElse(expensive())` avalia sempre; use orElseGet para fallback preguiçoso. |
| Stream API; 8/8 | Pipeline declarativo de transformação/redução | `names.stream().forEach(result::add)` → `names.stream().filter(s -> !s.isBlank()).toList()` | Menos estado compartilhado; stream é preguiçoso, de uso único, requer terminal. Evite I/O bloqueante em parallelStream e efeitos colaterais escondidos. Loops favorecem break, múltiplos acumuladores e tratamento de erro por item. Sem promessa universal de velocidade. |
| Collectors; 8/8 | Estratégias de redução, agrupamento e combinação | `toMap(Item::key, identity())` ignorando duplicatas → `toMap(Item::key, identity(), regraDeMerge)` se duplicatas forem válidas | Defina semântica de conflito, ordem e mutabilidade. Se duplicata é defeito, mantenha falha explícita. Use `groupingBy(Order::customerId, counting())` para contagem; não agrupe listas enormes só para contar. |
| Stream.toList; 16/16 | Materializa lista não modificável em ordem de encontro, quando definida | `stream.toList().add(x)` → `stream.collect(toCollection(ArrayList::new))` quando precisa modificar | Não assume ArrayList nem serialização. Pode conter null; diferente de List.of/copyOf. `Collectors.toList()` não promete implementação nem mutabilidade: declare o contrato requerido. |
| Sequenced Collections; 21/21 | Acesso uniforme a extremidades e visão reversa de coleções com ordem definida | `list.get(list.size()-1)` → `list.getLast()` após política para vazio | `reversed()` é visão, não cópia isolada; alterações podem refletir no original conforme suporte. Não promete ordem em HashSet/HashMap; use LinkedHashSet/LinkedHashMap quando ordem é requisito. Sem port para 17. |
| Gatherers; 22 P/24 final | Operações intermediárias extensíveis, como janelas | índice mutável dentro de map → `stream.gather(Gatherers.windowFixed(3)).toList()` | Útil quando map/filter não expressam transformação com estado; evite gatherer próprio para map simples. Janelas grandes aumentam memória; configure limite em mapConcurrent. Ausente 17/21; final em 25. |
| Collections.unmodifiable*; 1.2/1.2 | Views que bloqueiam mutação pela view | `this.items = Collections.unmodifiableList(items)` como suposto snapshot → `List.copyOf(items)` | A view acompanha mudanças do backing; adequada quando isso é intencional. Não confundir não modificável com profundamente imutável. |
| List.of/Set.of/Map.of; 9/9 | Fábricas de coleções não modificáveis pequenas | preencher ArrayList e expor como constante → `List.of("NEW", "DONE")` | Rejeitam null; Set.of rejeita duplicatas, Map.of chaves repetidas. Ordem de Set/Map.of não é contrato. Para mapa maior use Map.ofEntries; para mutação, estrutura mutável. |
| List.copyOf/Set.copyOf/Map.copyOf; 10/10 | Snapshot não modificável de elementos/chaves/valores atuais | `this.items = items` → `this.items = List.copyOf(items)` | Não copia objetos internos nem garante nova instância se já apropriada; rejeita null. Set.copyOf colapsa duplicatas. Se null é contrato válido, cópia em ArrayList + view não modificável pode ser necessária. |
| Generics; 5/5 | Tipos parametrizados para segurança em compilação | `List raw = new ArrayList();` → `List<String> names = new ArrayList<>();` | Use `? extends T` para fonte e `? super T` para destino (PECS); invariância impede tratar List<Integer> como List<Number>. Evite casts unchecked e raw types. Erasure impede `new T()` e `instanceof List<String>`; wildcard `List<?>` é permitido. |
| Comparator; 1.2; composição desde 8 | Ordenação externa ao tipo | `(a,b) -> a.age()-b.age()` → `Comparator.comparingInt(Person::age).thenComparing(Person::name)` | Evita overflow/boxing desnecessário; defina nullsFirst/Last e estabilidade exigida. Em TreeSet/TreeMap, compare==0 identifica equivalência de chave; não descarte pessoas por ordenar só idade. Comparable cabe à ordem natural. |
| java.time; 8/8 | Tipos temporais separados por significado | `LocalDateTime.now()` para instante global → `Instant.now(clock)` | Injete Clock para testes; LocalDate para data civil, ZonedDateTime quando zona/regras DST importam. Evite converter fuso implicitamente; Duration é tempo decorrido e Period calendário. APIs imutáveis; não imponha UTC a aniversários/datas civis. |
| BigDecimal; 1.1/1.1 | Decimal com precisão/escala controladas | `new BigDecimal(0.1)` → `new BigDecimal("0.10")` | Não representa moeda sozinho: associe Currency e regra de arredondamento. `equals` inclui escala; compareTo compara valor numérico. Divisão pode requerer escala/RoundingMode. Inteiros em unidades mínimas também podem ser adequados com controle de overflow e moeda. |

## Decisões de domínio que não cabem em atalhos

Dinheiro: não invente HALF_UP ou HALF_EVEN como regra universal. Preserve o contrato de arredondamento e o momento da aplicação; arredondar cada item versus total muda resultado. Exemplo com regra **explicitamente definida** de duas casas/HALF_EVEN:
```java
BigDecimal total = unitPrice.multiply(BigDecimal.valueOf(quantity))
    .setScale(2, RoundingMode.HALF_EVEN);
```
EVITAR reduzir qualquer moeda a duas casas sem especificação. Para quantidades/fracionamentos, valide unidades e escala. Use compareTo para limites numéricos e equals quando a escala integra o contrato.

Datas: um horário local pode ser inexistente ou ambíguo em DST. Defina política de escolha/rejeição na fronteira; não simplesmente acrescente um offset fixo. Serialização e banco devem preservar o significado acordado.

Streams: reducers paralelos exigem associatividade, identidade válida e ausência de interferência. `reduce(0, (a,b) -> a-b)` não é uma redução paralela correta. Para soma use operação associativa com semântica de overflow adequada. Streams de I/O como Files.lines precisam de try-with-resources.
